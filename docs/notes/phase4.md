## Фактична форма відповіді `query` (те, під що побудовано UI)

`sidecar/src/modules/rag/engine.js → processQuery()` має **два різні виходи**.

1. Ранній вихід, коли пошук нічого не дав (`engine.js:86-94`):

```js
{ response, contextApps: [], executionTimeMs, recommendedApp: "NOT_FOUND", retrievalStats }
```

Полів `alternativeApps`, `rawLlmOutput`, `ollamaMetrics` тут **немає**.

2. Звичайний вихід (`engine.js:227-236`):

```js
{ response, rawLlmOutput, recommendedApp, alternativeApps, contextApps,
  executionTimeMs, ollamaMetrics, retrievalStats }
```

`recommendedApp` — це або назва програми, або один із трьох маркерів:
`"NOT_FOUND"`, `"INVALID_QUERY"`, `"Не визначено"`.

`response` — Markdown-рядок, зібраний самим движком (а не LLM). При вдалому
збігу він завжди має вигляд:

```
**<Назва програми>**

<пояснення LLM (поле reason з JSON)>

**📄 Повна стаття довідки (<App> - <Title>):**

<повний текст статті з БД>
```

`alternativeApps` — **лише масив назв** (рядки). Ані описів, ані кроків, ані
скорів для них не повертається: це `contextApps` мінус рекомендована програма.
Тому альтернативи в UI не можуть мати «подробиць» — розгортання пропонує
перепитати саме про цю програму.

JSON від LLM (`prompts.js`, `config.rag.enableJsonFormat: true`) має схему
`{isMatch: boolean, reason: string, sourceId: number|null}` — але **до фронтенду
він не доходить**: движок сам розбирає його і склеює Markdown. Фронтенд читає
`recommendedApp` + `response`, і більше нічого йому не треба.

## Знайдені баги (не виправлялись)

1. `engine.js:20` — параметр `searchMode` мертвий: усі гілки нижче читають
   `config.rag.searchMode`, а не аргумент. Через RPC `query` його передати
   неможливо, хоч контракт `rpc.md` його й декларує (`excludeLocal` працює).
2. `engine.js:86-94` — форма результату нестабільна між гілками (див. вище):
   у ранньому виході бракує трьох полів, які є у звичайному. Клієнт мусить
   перевіряти кожне поле; `parseAnswer.js` це робить.
3. `engine.js:203-211` — текстова гілка (`enableJsonFormat: false`): якщо тег
   `[SOURCE_ID: X]` є, але X поза межами `parentDocuments`, `recommendedApp`
   лишається `null` → `"Не визначено"`, а в `response` доїжджає сирий текст LLM
   разом із тегом. Перевірки `INVALID_QUERY` у цій вітці немає взагалі
   (вона лише в `else`). UI обробляє це як окремий стан «точної рекомендації
   немає» і вирізає тег регуляркою.
4. `engine.js:224` — `alternativeApps = uniqueApps.filter(a => a !== recommendedApp)`.
   Коли `recommendedApp` дорівнює `"NOT_FOUND"` чи `"INVALID_QUERY"`, туди
   потрапляють **усі** знайдені програми, тобто найкращі з поганих збігів. UI
   свідомо не показує їх як відповідь — лише згадує муто, чию документацію
   переглянуто.
5. `engine.js:77-84` — поріг `_distance < 0.95` застосовується **тільки** для
   `searchMode: "vector"`. У поточному конфізі стоїть `"hybrid"`, де RRF-скор
   не порівнюється з жодним порогом, тому чанки в `relevantChunks` є майже
   завжди і рішення «нічого не знайдено» повністю на совісті LLM.
6. Скасування, `sidecar/src/rpc/methods.js:334` — `job.cancel` чесно повертає
   `cancelled: false`: перервати `processQuery` нічим. Кнопка «Скасувати» в UI
   відв'язує інтерфейс від результату (це працює миттєво) і додатково смикає
   `job.cancel`, але LLM на бекенді доїде до кінця.
7. Немає легального способу дізнатись `id` запиту: `rpc_call` у
   `src-tauri/src/sidecar.rs:211` генерує його всередині й повертає лише
   `result`. Єдине місце, де фронтенд бачить `id`, — кадри
   `sidecar://progress`. Тому `useSearch` виловлює `id` звідти. Наслідок: якщо
   скасувати до першого кадру прогресу, викликати `job.cancel` нічим.
8. `rpc_call` відхиляє проміс **рядком**, а не `Error` (Rust `Result<_, String>`).
   `humanizeError()` це враховує; будь-який інший код, що робить
   `err.message`, отримає `undefined`.
9. Кадри `sidecar://progress` не несуть назви методу — лише `id`. Розрізнити
   прогрес пошуку і прогрес пайплайна з панелі розробника неможливо. Зараз
   каркас показує лише один режим за раз, тому не критично, але якщо колись
   два модулі працюватимуть одночасно — індикатори переплутаються.

## Рішення в UI, які варто знати

- Текст статті з довідки рендериться через `marked`, але сирий HTML із джерела
  нейтралізується (токен `html` віддається як текст). Скрапнута документація —
  це недовірений вміст, у Tauri-вебв'ю XSS коштує дорого.
- Довга стаття (> 900 символів) згортається з градієнтом і кнопкою
  «Показати статтю повністю» — Enter по вибраній головній картці робить те саме.
- Стрілки ↑↓ обходять головну картку (індекс 0) і альтернативи. Поки щось
  вибрано, Enter діє на вибір, а не запускає новий пошук; Esc спершу знімає
  вибір, потім чистить усе. Фокус завжди лишається в полі вводу.
- Під фіксований футер каркаса (~28px) залишено `padding-bottom: 44px`.
- Глобальний хоткей виклику вікна не робився — це потребує Rust (окрема фаза).
