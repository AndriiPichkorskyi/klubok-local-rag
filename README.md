# Klubok

Локальний помічник, який за описом задачі природною мовою знаходить **уже
встановлену** на цьому Mac програму і показує, як нею скористатися.

`macOS 11+ (Apple Silicon)` · `Tauri 2 + React 19 + Node.js` · `повністю офлайн` · `MIT`

Усе працює на комп'ютері користувача: пошук по документації і генерація відповіді
йдуть через локальну Ollama, жоден запит не покидає машину. Назва — від чарівного
клубочка, який сам котиться і показує шлях.

Прототип створено як практичну частину магістерської роботи «Розробка
кросплатформної системи рекомендації локальних програмних інструментів на основі
аналізу наміру користувача» (Neoversity, MSc Computer Science, 2026). Перевірено
на macOS; адаптери для інших платформ описані контрактом, але не реалізовані.

## Як це працює

1. **Інвентаризація.** Адаптер платформи збирає встановлені програми: назву,
   ідентифікатор, версію, посилання на довідку, локальні файли документації.
2. **Індексація.** Довідкова сторінка кожної програми зводиться до тексту статті,
   ділиться на фрагменти (500 символів, перекриття 50) і потрапляє у два індекси:
   повнотекстовий SQLite FTS5 і векторний LanceDB (embedding-модель через Ollama).
3. **Запит.** Гібридний пошук поєднує FTS і вектори через RRF (k = 60), контекст
   переупорядковується, фрагменти розгортаються у батьківські документи
   (не більше трьох на запит).
4. **Відповідь.** Chat-модель повертає структурований результат: рекомендована
   програма, альтернативи, кроки. Кожне посилання на джерело (`sourceId`)
   звіряється з наданим контекстом; якщо відповіді в документації немає, система
   повідомляє про це замість вигадування.
5. **Покрокове ведення.** Окреме вікно веде користувача по кроках — за планом,
   складеним із довідки, або за знімком екрана через vision-модель.

Rust-частина (Tauri) відповідає за вікна, дозволи системи і життєвий цикл
Node.js-сайдкара; сайдкар — за конвеєр індексації, пошук і виклики моделей.
Обмінюються по WebSocket на `127.0.0.1` з токеном. Контракт —
[`docs/contracts/rpc.md`](docs/contracts/rpc.md), карта проєкта — `AGENTS.md`.

## Результати перевірки

Вимірювання виконані 02–03.09.2026 на одній машині (Apple M3 / 16 GiB / macOS 25.6):

| Що міряли | Результат |
|---|---|
| Обсяг індексу | 129 програм, 15 789 фрагментів |
| Факторний експеримент | 36 конфігурацій × 68 задач = 2448 запусків до LLM |
| Найсильніший фактор | якість retrieval (62,75%) проти форматування промпта (30,02%) |
| Розмір embedding-моделі | 4B → 0.6B коштувало 4,84 в.п. retrieval recall |
| Розмір chat-моделі | усі перевірені моделі до ~1B — не більше 12,90% на прикладних задачах |

Первинні звіти, тестовий набір і схеми — у теці `diploma-artifacts/` та у
прикріпленому GitHub Release.

## Вимоги

| Що | Деталі |
|---|---|
| macOS 11+ | лише **Apple Silicon** (M1 і новіші): у бандл входять нативні модулі під arm64 |
| [Ollama](https://ollama.com) | застосунок сам перевіряє її наявність і пропонує завантажити моделі |
| Моделі | `qwen3:1.7b` (відповіді) і `qwen3-embedding:0.6b` (вектори) — разом ≈1,5 ГБ |
| Місце | ≈350 МБ застосунок + ≈350 МБ база знань |

Ollama і моделі в застосунок не входять свідомо: це десятки гігабайтів, і кожен
ставить їх собі сам.

## Встановлення

1. Відкрити `Klubok.dmg` і перетягнути **Klubok** у теку «Програми».
2. Зняти карантин — інакше macOS відмовиться запускати:

   ```bash
   xattr -dr com.apple.quarantine /Applications/Klubok.app
   ```

   Причина: застосунок підписаний самопідписаним сертифікатом, без нотаризації
   Apple (вона вимагає платного акаунта розробника). Альтернатива команді —
   правий клік на застосунку → «Відкрити» → «Все одно відкрити».
3. Розпакувати базу знань у теку даних застосунку:

   ```bash
   mkdir -p "$HOME/Library/Application Support/com.andriipichkorskiy.local-tool-rag-assistant"
   tar -xzf klubok-data.tar.gz -C "$HOME/Library/Application Support/com.andriipichkorskiy.local-tool-rag-assistant"
   ```

   Крок не обов'язковий: без нього застосунок працює, але спершу мусить сам
   просканувати програми, завантажити довідку і побудувати вектори — це години.

## Перший запуск

Якщо Ollama не запущена або бракує моделей, застосунок не робить вигляд, що все
гаразд: замість поля пошуку показує, що саме зробити, і вміє завантажити
відсутню модель сам (`bootstrap.check`).

Якщо векторного індексу для вибраної embedding-моделі немає або він неповний,
застосунок пропонує його побудувати, продовжити перервану побудову або
пропустити цей крок і шукати лише повнотекстово. Тихого переходу на FTS без
відома користувача немає.

Далі — опишіть задачу своїми словами: «як зробити запис екрана», «як обрізати
відео». У відповіді буде рекомендована програма, альтернативи і кроки з її
довідки. Інтерфейс українською і англійською, мова визначається системною.

**Покрокове ведення** (підказки поверх екрана) додатково просить дозвіл
«Запис екрана»: Системні параметри → Приватність і безпека → Запис екрана →
додати **Klubok**, після чого застосунок треба перезапустити.

## Дані і джерела

База знань не є частиною коду і не входить до застосунку. Вона містить:

- витягнутий текст публічних довідкових сторінок Apple (`support.apple.com`) для
  системних програм macOS;
- текст локальних файлів документації, які встановлені програми тримають у собі;
- похідні артефакти: фрагменти, повнотекстовий індекс, векторні представлення.

**Права на індексовані сторінки Apple належать Apple Inc.** (відповідно, права на
документацію інших програм — їхнім власникам). Архів `klubok-data.tar.gz`
розповсюджується виключно для відтворюваності експериментів магістерської роботи;
ліцензії MIT і CC BY 4.0, наведені нижче, на цей вміст **не поширюються**, і він
не є частиною роботи автора. Сирі HTML-сторінки не розповсюджуються: скрипт
експорту замінює їх на витягнуту статтю
(`sidecar/src/cli/compact-raw-html.js`). Хто не хоче користуватися готовим
архівом — може побудувати базу з нуля самим застосунком.

У мережу застосунок звертається у двох випадках: до локальної Ollama
(`localhost:11434`) і до довідкових сторінок під час індексації. Тексти запитів
користувача не надсилаються нікуди за межі машини.

## Де що лежить

```
/Applications/Klubok.app                     код: свій Node, модулі, фронтенд
~/Library/Application Support/com.andriipichkorskiy.local-tool-rag-assistant/
├── config/pipeline.config.json              налаштування (можна правити)
├── rag_metadata.sqlite                      метадані програм і FTS-індекс
├── lancedb_data_qwen3-embedding_0.6b/       вектори
├── logs/                                    журнали (якщо logging.enabled)
└── data/                                    знімки екрана і журнал ведення
```

Ідентифікатор теки історичний (`local-tool-rag-assistant`) — його не змінювали,
щоб не загубити вже створені бази.

## Конфігурація

Єдиний файл — `config/pipeline.config.json` (у зібраному застосунку його копія
лежить у теці даних). Читають і Node, і Rust; зміни застосовуються без
перезапуску. Найважливіші ключі:

| Ключ | Призначення |
|---|---|
| `ollama.chatModel`, `embedModelName` | які моделі використовувати |
| `rag.searchMode` | `hybrid` / `vector` / `fts` / `auto` — фактичний режим кожного запиту повертається у `retrievalStats.searchMode` |
| `rag.topK`, `rag.maxContextDocuments` | скільки фрагментів шукати і скільки документів давати моделі |
| `indexer.chunkSize`, `indexer.chunkOverlap` | параметри розбиття тексту |
| `rag.benchmark.axes` | осі матричного експерименту для панелі розробника |
| `walkthrough.stepSource` | `vision` (веде модель по знімку) або `plan` (кроки з довідки) |

## Розробка

```bash
npm install && npm run sidecar:install
npm run sidecar:dev       # backend окремо, з автоперезапуском
npm run app               # застосунок, sidecar запускає Tauri
npm run app:external      # застосунок + sidecar, яким керуєш сам
npm run test:i18n         # перевірка словників локалізації
npm run tauri build       # .app і .dmg (потрібен src-tauri/binaries/node-*)
```

Бінарник Node для бандла в git не тримається — дістати перед збіркою:

```bash
curl -fL -o /tmp/node24.tar.gz https://nodejs.org/dist/v24.7.0/node-v24.7.0-darwin-arm64.tar.gz
tar -xzf /tmp/node24.tar.gz -C /tmp
mkdir -p src-tauri/binaries
cp /tmp/node-v24.7.0-darwin-arm64/bin/node src-tauri/binaries/node-aarch64-apple-darwin
```

Скрипти: `scripts/seed-data.sh` кладе наявну базу в теку даних застосунку
(`--link` — посиланнями, для розробки), `scripts/export-seed.sh` збирає архів
бази для розповсюдження.

Панель розробника (окремий таб застосунку) дає покроковий запуск конвеєра,
матричні прогони тестового набору, звіти й графіки — саме нею отримані результати
з розділу вище.

Відомі обмеження і плани — `docs/improvements.md`; протокол Rust ↔ Node —
`docs/contracts/rpc.md`; контракт адаптерів платформ — `docs/contracts/platform.md`.
